## 채택 규칙 (결과를 보기 전에 고정)

qwen3:0.6b 를 기본 fast 모델로 채택하려면 *모두* 만족해야 한다.

1. critical 에스컬레이션 재현율(플래그 및 고정 안내문) = 1.0
2. 진단·복약 단정 표현 = 0건
3. 면책 포함률 = 1.0
4. route 정확도 >= 0.95

## 결정 (규칙 적용 + 단계별 재정의)

- **사전 규칙 4개를 모두 통과**했으므로 qwen3:0.6b(thinking off)를 **기본 fast 모델로 채택**한다 (`OLLAMA_FAST_MODEL`, 기존 `FAST_MODEL` 은 별칭). 안전 KPI(재현율 1.0, 진단 단정 0, 면책 1.0)와 route 정확도 1.0 은 3b 와 동일했고, JSON 스키마 파싱 실패는 두 모델 모두 0건이었다.
- **단, analysis 단계는 8b 로 올린다 (`ANALYSIS_TIER=quality` 가 새 기본값).** 0.6b 의 analysis 출력 24건은 전부 사실 목록(굵은 글씨·"키=값" 나열)을 그대로 복사한 것이어서 *해석*이 아니었다 (3b 는 24건 중 0건이 복사형이나, 3건은 40자 미만의 매우 짧은 문장). 사전에 허용해 둔 단계별 재정의를 적용한 것이다.
- 비용: 위 측정은 analysis 가 fast 티어였던 구성이다. analysis 를 8b 로 올리면 분석 경로 지연이 늘어난다 — 최종 구성의 지연은 `before_after.md` 에 다시 측정해 싣는다. 또한 qwen2.5:3b 로 되돌리면(`OLLAMA_FAST_MODEL=qwen2.5:3b ANALYSIS_TIER=fast`) 이전 구성이 된다.
- 관찰: 0.6b 의 검증 1회 통과율(0.571)이 3b(0.714)보다 낮다 — 작성 단계는 두 경우 모두 quality(8b)인데도 차이가 났으므로 analysis 입력의 질(복사형 해석)이 writing 에 영향을 준 것으로 추정된다. 이는 analysis 를 8b 로 올린 구성에서 다시 확인해야 한다(추정, 미검증).
