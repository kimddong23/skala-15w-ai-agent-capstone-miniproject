# 회귀 테스트용 쿼리 (손으로 쳐 보는 목록)

브라우저 화면(`bash sh/run_frontend.sh`) 또는 `curl`로 아래 질문을 하나씩 입력해 보면서 코드를 따라가는 용도다. 각 행이 **어떤 분기나 동작을 확인하는지**를 적었다.
사용자 `U01`~`U15`는 가명이다. 데이터는 2016-03-29~05-12이고 "최근 N일"의 끝은 각 사용자의 마지막 기록 시각이다.
README의 질의 예시 표는 이 문서로 옮겼다. 화면 캡처가 있는 사용 예 6가지는 [사용자 가이드](manual_ollma.md)에 있다 (사용 예 1 = #1·3, 2 = #5, 3 = #5·8, 4 = #6·7, 5 = 화면 전체, 6 = #13~15·20).
(`curl` 예: `curl -s -X POST localhost:8100/chat -H 'Content-Type: application/json' -d '{"message":"U05 최근 30일 심박 이상 점검해줘","thread_id":"t1"}'`. 같은 `thread_id`를 쓰면 대화가 이어진다.)

## 쿼리 목록

| # | 쿼리 | 테스트 목적 |
|---|---|---|
| 1 | 안녕, 너는 누구야? | 인사말은 계획·조회 없이 simple로 바로 답한다. 소개 문구와 면책이 나온다 |
| 2 | 제 이름은 민수입니다 → (같은 대화에서) 제 이름이 뭐였죠? | **대화 기억.** 같은 `thread_id`에서 말한 이름(또는 나이)을 되물으면 코드가 기록에서 "민수님이라고 말씀하셨어요"로 답한다. 도구 호출 없이 simple이고, LLM 답이 이름을 틀리면 코드가 결정론적 답으로 바꾼다. 말한 적 없는 정보는 "아직 이름을 말씀해 주지 않으셨어요"라고 인정하고 다른 thread로 새지 않는다. `CHECKPOINTER=sqlite`면 서버를 재시작한 뒤에도 기억한다 (`tests/test_chat_memory.py`) |

## 기대하는 실행 과정

|---|---|---|
| 1 | `route_decided`(simple) | `plan_created`, `task_*` |
| 3 | `route_decided`(simple), `task_started`/`task_completed`(검색, 근거 N건) | `plan_created`, `anomalies_found` |

| 6 | 위와 같고 `replan`(48.6% < 50% → 14일)이 `anomalies_found` 뒤에 한 번 | `safety_escalation` |

관찰:

- **#2 이름 기억**: 이름과 나이를 기억한다(LLM 없음 실행으로 다시 확인: 같은 thread에서 "민수님이라고 말씀하셨어요", 나이 "30세라고 말씀하셨어요", 말하지 않은 값은 "아직 말씀해 주지 않으셨어요"). 기억은 체크포인터에 저장된 메시지에서 읽으므로 sqlite에서는 서버 재시작 뒤에도 유지된다(`tests/test_chat_memory.py`가 확인, 이번에 재시작 장면을 손으로 다시 해 보지는 않았다). LLM을 켠 실행은 이번에 다시 보지 않았다.
- **#4 운동 질문**: LLM 없음의 키워드 폴백은 "이상"이라는 단어 때문에 점검 요청으로 보고 사용자 선택 안내로 간다(조회는 하지 않는다). LLM을 켠 개발 평가(`eval/results/agent_eval.md`)에서는 simple로 분류된다.
- **#10 사용자 비교**: `U01이랑 U05 최근 30일 비교해줘`가 analysis로 가서 두 사용자를 병렬로 조회한다(LLM 없음 실행: 이상 7건, `safety_escalation`의 안내문에 "해당 사용자: U01, U05", U01 커버리지 47.7% 한계 문구, 검증 1회 통과). 기간 없이 `U01이랑 U05 비교해줘`(7일)는 U01 재계획, 한계 문구까지 나온 뒤 검증이 두 번 실패해 템플릿으로 대체됐다(`degraded`). 사용자 한 명은 이상이 0건이고 다른 사용자는 있어서 "구간이 감지되지 않았습니다" 문장이 이상 없음 서술로 걸린 것으로 보이며 개선 후보다(LLM 없음 실행). 한도(3명)를 넘는 요청은 제외된 사용자를 밝힌다.
- **#18 인젝션**: 사용자 ID를 함께 줘야 점검 경로로 간다. ID가 없으면 사용자 선택 안내가 나온다. LLM을 켠 실행에서는 검증기가 "이상이 감지되었는데 '이상 없음'으로 읽히는 서술"을 두 번 반려했고(`validation` 시도 2회), 템플릿 리포트로 대체되어(`degraded`) 실제 이상 1건이 그대로 나왔다(51.5초). 의도한 방어가 동작한 사례다.
- **#9 지난주 수면 질문 (LLM 켬)**: 이상은 0건이고 검증을 통과했다. 그런데 리포트가 "수면 중 평균 심박은 64.6bpm으로 정상 범위에 있으며 ... 이상 없으므로 추가적인 주의가 필요하지 않습니다"라고 썼다. 데이터 한계가 없는(커버리지 95%) 경우라 현재 검증기 규칙("정상 범위" 서술은 데이터가 제한적일 때만 막음, "추가 검사 필요 없음" 류 패턴)이 이 문장을 잡지 못했다. **검증기의 알려진 틈**이며 개선 후보다.
- **#3 일반 질문 (LLM 켬)**: 가이드라인을 인용한 답변이 나오고 끝에 출처(`heart-rate-ranges` 문서 제목)가 붙는다.
